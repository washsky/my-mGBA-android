# mGBA Android 存档使用说明

“存档是什么”和“文件放在哪里”是两件事。内部、外部只是位置，不是两种存档格式。

| 文件 | 保存的内容 | 使用方式 |
| --- | --- | --- |
| `.gba`、`.gb`、`.gbc` | 游戏本体 | 打开游戏；不包含你这次游玩的进度 |
| `.sav` | 游戏自己“保存／记录”后的数据 | 在游戏菜单中保存，再从标题画面选择继续；适合迁移到支持相同游戏存档格式的模拟器 |
| `.ss`、`.ss1`、`.state2`、`.stateX` 等 | 某一瞬间的模拟器状态 | 读取后回到那一刻；要求相同 ROM 和兼容的即时存档格式 |

## 日常保存

1. 优先在游戏里选择“保存”，例如宝可梦的游戏菜单 → 保存。这会更新当前游戏对应的 `.sav`。
2. 想随时回到某一画面，用 mGBA 菜单 → 存档快照 → 新建快照。每次单独保存进度和游戏截图，可从列表选取，查看大图后读取，也可在“更多”里重命名或导出。快照数量只受设备存储空间限制。
   从游戏库长按某个游戏，也可以查看并加载它的快照。原有 1～9 号位在“旧版存档位”中。
3. 除非开启了相应的自动保存，不能把直接退出应用当作已经保存即时进度。

## 内部工作副本与外部文件

导入 ROM 或存档时，mGBA 会建立自己管理的工作副本，原文件保留。之后继续游戏、保存游戏或保存即时存档，都不会自动更新外面的旧 `.state2`。

从“游戏库”或“最近使用”打开游戏即可。每次打开其他 ROM，应用按 SHA-256 内容校验归档：同一本体改名、换位置也复用同一份库内进度；不同内容的改版／汉化版分开保存，不自动混用存档。不要靠手动挪动内部文件来管理日常进度。

## 统一游戏目录

默认目录是本应用专属存储的 `Games`，可以从“游戏库 → 浏览统一目录”进入。每个游戏使用一个“名称＋校验值”文件夹，包含：

| 文件或子目录 | 用途 |
| --- | --- |
| ROM、同名 `.sav`、`.ss1`～`.ss9` | 游戏本体、游戏内存档、旧版即时存档位 |
| `Snapshots` | 可命名的快照，每份 `.ss` 自带截图 |
| `Imports` | 导入的外部快照、游戏存档、金手指留底 |
| `Backups` | 加载／修改前的回退快照和旧金手指文件 |
| `Exports` | 导出时生成的新副本，之后仍需选择公共保存位置 |
| `LegacyBackups` | 第一次归档时保留的各份旧进度副本 |
| `Network` | 各次联机的恢复记录 |
| `game.properties` | 游戏库信息，请勿手动改动 |

旧游戏在下次打开时归档，原目录和原文件保留。发现多份相同 ROM 的旧进度时，可以选择沿用哪一份，其余进度也保留副本。自定义即时存档位置继续用于旧版存档位和自动即时存档，命名快照保存在游戏库。旧版文件可从“文件管理 → 更多位置 → 旧版保留文件”找回。

`Games` 属于应用专属目录，卸载时仍可能被清理；备份请导出到 Download 或自己的公共文件夹。

外部文件名中的 `2` 不会自动绑定到本应用的 2 号存档位；打开 `kdygyl.state2` 是加载这个文件所记录的进度。扩展名能被识别，并不意味着其他模拟器的任意私有格式都兼容。

## 导出最新进度、换手机

- 推荐备份：mGBA 菜单 → 存档管理 → 导出当前即时进度。也可从存档快照的预览页选择“更多 → 导出快照”，复制已选快照及其截图。
- 迁移游戏内存档：先在游戏里“保存”，再选“导出游戏存档（.sav）”。导出 `.sav` 不会替你执行游戏里的保存操作。
- 选择 Download 或自己的公共备份文件夹。另一台手机先打开相同 ROM，再导入相应文件；即时存档还要求格式／版本兼容。
- 文件管理中的“导出此文件的副本”只复制那份已选文件。它不会把旧文件更新为你现在的进度；需要最新进度时用“存档管理”的导出入口。

## 导入和自动备份

外部即时存档导入前会保存当前进度的回退副本，失败时尝试恢复。可以在“查看自动备份”中找回之前的进度。外部即时存档若包含游戏保存数据，导入时也会恢复那一份数据，因此加载旧快照后不要以为 `.sav` 一定仍是较新的进度。

自动回退副本仍在应用管理的目录里，不能代替导出到公共文件夹的备份。卸载或清除应用数据前请先导出；`Android/data/应用包名` 虽然在共享存储下，也属于应用专属目录，卸载时会被清理。原来的其他应用文件不要删除。
